Components and the state block

// core/pod_check.h: Boost.PFR-style aggregate walk (brace-init field counting + structured bindings)
template <class F>
constexpr bool field_ok() {
    if constexpr (std::is_arithmetic_v<F> || std::is_enum_v<F>) return true;
    else if constexpr (IsArray<F>::value) return field_ok<typename IsArray<F>::Elem>();
    else if constexpr (std::is_pointer_v<F> || std::is_reference_v<F> ||
                       std::is_member_pointer_v<F> || std::is_array_v<F>) return false;
    else if constexpr (std::is_aggregate_v<F> && std::is_trivially_copyable_v<F> && std::is_standard_layout_v<F>)
        return decltype(fields_ok(std::declval<F&>()))::value;   // recurse into nested structs
    else return false;
}

Components are plain structs-of-scalars in one aggregate, which is natural C++. But pointer-freedom isn't a language property: it took a ~100-line template trick (with a hand-written 24-rung structured-binding ladder) plus -Wpadded, which forces manual `reserved0..2` fields and stores enums as raw `u8` to control size. All compile-time, at least.

#[derive(Pod)] is the strongest pointer-freedom check of the three languages: any reference, Box, Vec, raw pointer or implicit padding is a compile error, so bytes_of(&state) is canonical by construction. The 65 KB block is created with bytemuck::zeroed_box() so it never lands on the stack.

template <int N>
void pool_free(SlotPool<N>& p, int slot) {
    UNI_ASSERT(p.count > 0);
    p.next_free[slot] = p.free_head;
    p.free_head = (u16)slot;
    --p.count;
}

// pod_check.h. Zero per-component boilerplate for names and types. C++26 reflection (P2996) isn't in
// upstream clang or MSVC yet; PFR's BOOST_PFR_USE_CPP26_REFLECTION is the migration switch.
#include <boost/pfr.hpp>

template <class T, class Fn>                          // fn(std::string_view path, auto& scalar)
void visit_fields(T& obj, std::string& path, Fn&& fn) {
    using U = std::remove_const_t<T>;
    if constexpr (std::is_arithmetic_v<U> || std::is_enum_v<U>) {
        fn(std::string_view(path), obj);
    } else if constexpr (uni::pod::IsArray<U>::value) {  // uni::Array holds a C array: PFR can't walk it
        for (int i = 0; i < U::size(); ++i) {
            const usize mark = path.size();
            path += '[' + std::to_string(i) + ']'; visit_fields(obj[i], path, fn); path.resize(mark);
        }
    } else {
        constexpr auto names = boost::pfr::names_as_array<U>();
        boost::pfr::for_each_field(obj, [&](auto& field, std::size_t i) {
            const usize mark = path.size();
            path += path.empty() ? "" : "."; path += names[i]; visit_fields(field, path, fn); path.resize(mark);
        });
    }
}

Strengths and pain points, in each implementer's words

C++

Strengths

  • Box3D (C) and godot-cpp are used natively: box3d.h is included directly, so new physics calls need no FFI declarations or layout mirroring. The 227-line physics/ module is a convenience wrapper, not a binding.
  • The POD block plus memcpy is the idiomatic path: save 8 µs and restore 11 µs, and with no padding the raw block bytes are the canonical checksum and the portable snapshot format, guarded by a constexpr layout hash.
  • Complete, uniform control over floats and UB via compiler flags shared with Box3D's C build. Windows (clang-cl, Winsock, timers) worked first time, and ASan+UBSan and TSan are clean, including late join.
  • Zero-cost abstractions where wanted: templated SlotPool<N>, lambda-taking `for_neighbours`, RAII `phys::Snapshot`, defaulted `operator==` for input prediction checks, and `unique_ptr` composition of socket → netsim → host → client.
  • Fast iteration: 2 s fresh build and 0.4 s for a one-line sim edit. The Godot GDExtension variant is 5.5 s fresh with a build profile, and the view's own work is 0.1–0.2 ms/frame.
  • Systems and the schedule are plain functions and loops over fixed arrays: easy for humans and agents to read, and iteration order (which determinism depends on) is explicit.

Pain points

  • No reflection in C++20: proving the block is pointer-free took a ~100-line Boost.PFR-style trick with a hand-written 24-rung structured-binding ladder, and field NAMES (for an inspector, desync diff or config) still need Boost.PFR or X-macros. C++26 reflection isn't in upstream clang or MSVC (likely 2027 or later).
  • Layout discipline is manual: -Wpadded as an error forces hand-placed `reserved0..2` fields and size asserts, and enums are stored as raw `u8` (`u8 kind; // EnemyKind`), giving up type safety to control bytes.
  • Serialization has no derive: each of 9 protocol messages has a hand-mirrored encode and decode (~220 lines), and the 4-byte input packing is written twice (protocol.cpp and input_log.cpp).
  • Safety is runtime-only: bounds checks exist only in dev builds (UNI_CHECKS, libc++ hardening), UB and data races are caught only by ASan/UBSan/TSan runs or sync-test, and the language allowed `reinterpret_cast` onto a private Box3D struct (world_state_ext.cpp) with no friction.
  • Determinism bans are not enforced: nothing stops `std::sin`, `<random>`, unordered-container iteration or uninitialized locals in sim code. The poison header, `-ftrivial-auto-var-init` and clang-tidy are still TODO.
  • Toolchain plumbing: CMake plus a per-platform flag translation layer (clang-cl `/clang:`, `/EHsc` kept only for MSVC STL headers), and godot-cpp's RTTI requirement conflicts with the sim's `-fno-rtti` (it crashed until the view TU enabled RTTI). There's no built-in test runner either: tests are CLI modes driven by Python.
Odin

Strengths

  • The state-block design is idiomatic Odin: fixed arrays, enumerated arrays (`[Enemy_Kind]Enemy_Stats`), a parapoly `Pool($T, $N)`, zero-init; snapshot = struct assignment, checksum = raw bytes, portable restore = one memcpy.
  • C interop is nearly free: 294 lines of hand bindings with `link_prefix`, by-value structs and 38 compile-time `#assert` layout checks; Godot's GDExtension C API bound via a generator in under a day with no calling-convention bugs.
  • Fast, cache-free builds: 0.4 s dev builds whether fresh or after a one-line edit, `odin check` in 0.05 s, nothing per worktree.
  • Rich RTTI at zero build cost: the 54-line POD walker, and inspector/field-by-name write/desync diff/JSON dumps need zero per-component code (sketches type-checked).
  • Best measured performance and smallest code: 0.62 ms step + 8-tick re-sim with bounds checks on, 3,851 lines total, plain loops with no borrow-checker friction across tables.
  • Small, regular language with built-in `odin test` (parallel, leak-tracking), `context.temp_allocator` for per-frame scratch, `or_return`/multiple returns for errors, and `#load`/`#config` for embedding and build switches.

Pain points

  • Pointer-freedom and no-padding are enforced by a startup/`odin test` RTTI walk, not the type system: a pointer or padding added to a component compiles and only panics at launch. The padding rule forces hand-placed `_pad` fields.
  • No interfaces/traits or methods: the transport is a struct of proc pointers + `rawptr` with an unchecked cast in every implementation, and the Godot API becomes 1,837 `Class_method(self, ...)` free functions with `using base_` embedding for subtyping.
  • No destructors/RAII: every heap object (channels, netsim queues, Box3D world states, Godot RefCounted objects) is freed by convention with `defer`/explicit close; the Godot bench's first version leaked 822 objects, and Godot node handles dangle after queue_free.
  • No derive/macros or compile-time execution: binary wire formats are written field by field (Input's 4-byte packing exists twice), and anything beyond RTTI (typed system registration, generated packers) would need a codegen step.
  • Determinism traps are not compiler-guarded (core:math transcendentals via libm, `matrix` FMA on arm64 only, poison float->int casts); today the policy is a comment, and a banned-API lint would be our own core:odin/parser tool.
  • Stdlib/toolchain maturity papercuts hit during phase 2: wrong streaming XXH3 digests in core:hash/xxhash, `foreign import` refusing absolute/#config paths, RADLINK mangling a quoted LIBPATH, CRT mismatch on Windows, and program-wide package names (`net` taken).
Rust

Strengths

  • bytemuck::Pod proves at compile time that the block has no pointers and no padding, so the checksum is xxh3(bytes_of(&state)), a snapshot is `*slot.block = *state` (7-8 us save), and the portable format is pod_read_unaligned. No unsafe is involved.
  • unsafe is confined by a workspace lint (unsafe_code = "forbid") to box3d-sys. Game, netcode and CLI code are entirely safe, and the C layouts are checked by const asserts with offset_of! plus a runtime check against the linked library.
  • Traits keep the architecture honest: netcode depends only on simcore and is generic over Simulation and InputSource; NetSim<D> wraps any Datagram and sits under the reliable lane with zero-cost composition; Send bounds make the thread hand-offs compile-checked.
  • Determinism comes mostly from defaults: no FMA contraction, no fast-math, defined float-to-int casts, overflow checks in dev. Traces matched across macOS ARM64, x86_64 (Rosetta), Linux and Windows, and over mixed-architecture UDP sessions.
  • Enums with data plus Option and `?` make the protocol and parsers exhaustive and total (a truncated packet decodes to None, never an out-of-bounds read). Result<_, String> keeps error paths explicit with 12 packages in the whole dependency tree.
  • Builds and tooling are good for a headless core: 5.8 s fresh, 0.4-0.5 s per edit, cargo test with in-file tests (including a layout test against the C library). gdext offers a mature, safe Godot path with 0.6 s edit rebuilds.

Pain points

  • Pod's rules turn the state block into C-style data: no bool, Option or Rust enums (flags are u8, enemy kind is a u8 index into KINDS, BodyRef uses a `live` sentinel), and padding must be written out as `_pad` fields, or the derive refuses to compile.
  • C binding cost: 679 hand-written lines (extern decls, 26 #[repr(C)] structs, const offset asserts, a runtime layout cross-check, SAFETY comments) for 28 Box3D functions. Restoring physics from bytes needed a pointer cast to a mirrored private C struct.
  • Generics with associated types don't erase easily: Datagram::Addr rules out Box<dyn Datagram>, so choosing loopback or UDP at runtime needs a hand-written `enum Sock` and duplicated match arms. Exposing state or events to a view would mean adding associated types (Block, Event) to the Simulation trait.
  • Borrow splitting shapes the code: Game::step destructures self, the Jacobi scratch buffer lives outside State and is passed separately, helpers that take all of &mut State can't run while a field is borrowed, and systems use index loops over SoA columns rather than iterator or query ergonomics.
  • No built-in reflection. An inspector, desync field diff or save files need a macro_rules! wrapper or more proc macros (serde, facet or bevy_reflect), and each proc macro adds uncached build time. serde's array support stops at [T; 32], which hits the 1200-long SoA columns.
  • Some determinism bans are only discipline: there is no clippy.toml banning f32::sin/mul_add/HashMap in sim crates, and CI doesn't run clippy. With Godot, gdext enforces borrows at runtime across engine callbacks, so a re-entrant signal hung the screenshot mode until base_mut() was held.

What might nudge the decision

If dev tooling and simplicity weigh most, Odin. Reflection is built in at zero cost, which is exactly what an in-game inspector, desync diff and config need. It's also the least code and the fastest loop. You pay in safety (no RAII, runtime-only layout checks), in polymorphism (proc-pointer structs), in maturity (a stdlib bug and two toolchain quirks in one phase), and in owning the Godot bindings.

If guarantees weigh most, Rust. The compiler proves the snapshot property and confines unsafe code, errors can't be ignored, and determinism mostly comes from defaults. You pay in binding code for every C library, in borrow-shaped data layout, and in macro-based reflection with a build-time cost.

If native reach weighs most, C++. Box3D, Steam, FMOD and godot-cpp are all used directly, with zero glue. You pay in reflection and serialization (nothing built in until C++26), and in safety that only exists when a sanitizer or sync-test happens to run the bad path.
