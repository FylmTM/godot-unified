# 06: UI frameworks (dev tools + game UI)

Researched 2026-11-07. Claims I couldn't confirm from a primary source are marked **(unverified)**. Version numbers
move fast here; re-check them before a spike.

## TL;DR and recommendation

**Use two layers now, and keep the door open to merging them later.**

1. **Dev tools: egui.** It's the clear winner on any Rust/wgpu host, Bevy included. Immediate mode suits our core
   design: all sim state lives in one block, and a tool just reads it every frame and emits edit commands. The
   ecosystem already has an inspector (`bevy-inspector-egui`), plots, docking and tiles. Agents write egui fluently,
   because it's plain Rust with lots of examples. Hot reload comes from Dioxus' `subsecond` hot-patching. Immediate
   mode is the best case for it: UI functions run every frame, so a patched function shows up on the next frame.
   On Godot, use Dear ImGui instead (`imgui-godot`).
2. **Game UI on Bevy: `bevy_ui` (Taffy layout, Parley text) + BSN templates + a CSS-style sheet with transitions
   (`bevy_flair`) + a small in-house "juice" kit** (tweens, springs, the FEEL.md §8 presets) + Bevy's built-in
   automatic directional navigation for gamepads. It renders in our renderer, it's ECS-native (UI reads sim
   resources like any other view system), it's free and in-process, and Bevy is building its own editor on the same
   stack (Feathers). The downside is churn: BSN syntax changed again in 0.20, and `.bsn` asset files aren't
   shipped yet.
3. **Game UI on Godot: Control nodes.** Mature, with themes, tweens, focus neighbours, MSDF fonts, OpenType text and
   a translation server. Nothing third-party beats them inside Godot.
4. **Watch list, not picks:** **Blitz/Dioxus Native** (HTML/CSS + RSX components on Stylo, Taffy, Parley and Vello)
   is the closest Rust match for s&box's Razor approach and the developer's taste, but it's pre-alpha for games:
   no gamepad navigation and texture-only Bevy integration. **PanGui** looks superb but isn't public (invite-only
   alpha, C# first, C++ transpile next, no Rust in the latest update, licence unknown). **NoesisGUI** has the
   highest game-UI ceiling, €195 for indies, and Hytale is moving to it. It's the fallback if the bevy_ui spike
   fails the "juicy" bar, at the cost of closed source and XAML.

**Can one framework serve both layers?** On Godot, yes: Control nodes run the Godot editor itself. On Bevy, the
intended future is yes (Feathers on bevy_ui for the editor, bevy_ui for games), but in late 2026 the egui tooling
(the inspector especially) is years ahead of Feathers. The split costs little: dev tools never ship to players, so
egui's look doesn't matter, and the two layers share nothing but the sim read API.

## Details

### egui (dev-tools pick)

egui 0.34 (2026-03-26) moved text rendering to `skrifa` for sharper glyphs and made `Ui`, not `Context`, the main
entry point. That's a typical yearly breaking change ([0.34.0 notes](https://newreleases.io/project/github/emilk/egui/release/0.34.0)).
`bevy_egui` tracks Bevy closely (0.40–0.41 for Bevy 0.19, 0.42 newest, [docs.rs](https://docs.rs/crate/bevy_egui/0.41.0),
[crates.io](https://crates.io/api/v1/crates/bevy_egui)). `bevy-inspector-egui` gives a reflection-driven entity and
resource inspector out of the box ([lib.rs](https://lib.rs/crates/bevy-inspector-egui)). Its newest release I found
is 0.36 for Bevy 0.18, so a Bevy 0.20 version is **unverified**.

- Fits our tools: the timeline scrub is a slider over snapshot indices, the net sim panel is sliders plus `egui_plot`
  graphs, the perf overlay is a plot, and tuning sliders write to text files. Since immediate-mode code only *reads*
  sim state and returns edit intents, tool edits can go through the same command channel as the agent API, which
  keeps replays honest.
- Styling ceiling: fine for tools. Juicy game UI would need hand-painted meshes. I found no shipped commercial game
  that uses egui for player-facing UI **(unverified either way)**.
- Text: a glyph atlas per size, no SDF. Complex-script shaping (Arabic, Indic) isn't supported **(unverified)**. CJK
  works with a fallback font. Fine for tools.
- Hot reload: `bevy_simple_subsecond_system` and `bevy_hotpatching_experiments` hot-patch systems through
  `dx serve --hot-patch`. Startup-spawned UI doesn't rerun after a patch, but immediate-mode UI does, every frame
  ([docs](https://docs.rs/bevy_simple_subsecond_system), upstream tracking [bevy#19296](https://github.com/bevyengine/bevy/issues/19296)).

### Dear ImGui

The C++ gold standard. On Rust, `imgui-rs` still works but is lightly maintained ([repo](https://github.com/imgui-rs/imgui-rs)).
`dear-imgui-rs` is the active Rust ecosystem, with docking, wgpu, ImPlot and ImGuizmo ([trendshift](https://trendshift.io/repositories/114546),
the old `dear-imgui` crate points to it: [README](https://docs.rs/crate/dear-imgui/0.3.0/source/README.md)). It only
wins on a C++ or Godot host: [`imgui-godot`](https://github.com/pkdawson/imgui-godot) supports Godot 4.2+ from C#, C++
and GDScript on Win/mac/Linux, under MIT.

### bevy_ui, BSN, Feathers (Bevy game-UI pick)

- **Timeline:** 0.17 (2025-09) added headless widgets and Feathers. 0.18 (2026-01) added BSN. 0.19 (2026-06-19)
  ported Feathers to BSN, added `EditableText` and moved text to Parley. 0.20 (2026-10-08) changed BSN syntax (`@`
  scene refs), added a `Ready` event, more Feathers widgets (list, dropdown, colour input, scrubbable number input),
  contextual theming, headless tabs, `em`/`rem` units, elliptical corner radii and inline images in text. Hot-reloadable
  `.bsn` asset files and a remote inspector are listed under "What's Next"
  ([0.20 notes](https://bevy.org/news/bevy-0-20/), [news index](https://bevy.org/news/), [0.19 recap](https://gamefromscratch.com/bevy-0-19-released/),
  [Feathers on BSN](https://docs.rs/crate/bevy/latest/source/_release-content/release-notes/more_widgets.md)).
- **Text:** `bevy_text` 0.19 depends on Parley (shaping, BiDi through ICU4X, HarfRust) instead of cosmic-text
  ([docs.rs](https://docs.rs/crate/bevy_text/0.19.0-rc.2), [Parley](https://github.com/linebender/parley)). Glyphs are
  rasterized into an atlas, and I found no MSDF path **(unverified)**. So a 1.15× scale pop on text either
  re-rasterizes or blurs slightly. Spike item.
- **Gamepad:** `AutoDirectionalNavigation` on UI entities gives 8-way automatic neighbours, with manual edges
  overriding them (for wrap-around or wheels). `bevy_input_focus` dispatches gamepad and keyboard events to the
  focused entity ([source](https://docs.rs/crate/bevy_input_focus/0.19.0-rc.1/source/src/directional_navigation.rs)).
  Bevy is the only Rust option here with this built in.
- **Styling/animation:** gradients, box shadows and UI materials (custom shaders) are built in. There are no tweens.
  [`bevy_flair`](https://github.com/eckz/bevy_flair) adds CSS stylesheets with transitions, `@keyframes` and hot
  reload (0.8 for Bevy 0.19, one maintainer). Its limits: one stylesheet per entity and no global sheets.
- **Reactive:** there is no official reactivity yet; BSN is declarative spawning. [`haalka`](https://github.com/databasedav/haalka)
  (FRP signals) is the most active community option, at Bevy 0.18 as of its last release. Our own HUD needs are
  small: about 10 widgets driven by a few sim values. A "derive from sim each frame, diff, then tween" system is
  enough, and avoids a reactive library.

### Blitz / Dioxus Native (watch)

A modular HTML/CSS engine: Stylo (Firefox's style system), Taffy, Parley and Vello on wgpu
([repo](https://github.com/DioxusLabs/blitz)). Dioxus 0.7 (2025-09) made it available to everyone but warns that CSS
features are missing ([release](https://dioxuslabs.com/blog/release-070)). Crate pages still say pre-alpha. The
Dioxus docs list "embed in a Bevy game" as a goal. Today that's done by community crates: `bevy_dioxus_render`
renders to a Vello texture shown as a Bevy image (Bevy 0.17) ([docs](https://docs.rs/bevy_dioxus_render)), and
`bevy_dioxus_sync` syncs state ([lib.rs](https://lib.rs/crates/bevy_dioxus_sync)). It's the most agent-friendly
format (HTML/CSS/RSX) and matches the s&box model, but it lacks gamepad navigation, texture compositing costs a
pass, and Vello's compute-heavy path on a Steam Deck is **unverified**. Re-check in 6–12 months.

### PanGui (watch)

From the Odin Inspector team (Sirenix). It's immediate-mode first with an optional retained layer, has no
dependencies, uses SDF shapes, and outputs rendering commands plus one shader under 1000 lines, so it drops into
any pipeline ([pangui.io](https://pangui.io)). The 2026-09-23 update covers a C#→C++ transpiler that passes all
tests, render effects (blur, glow, shadows, chromatic aberration…), BiDi and HarfBuzz/ICU shaping hooks, and
"inviting new beta applicants to the alpha with increasing regularity". It gives no public date, licence or price,
and doesn't mention Rust ([update](https://pangui.io/blog/07-progress-update-september),
[handmade.network](https://handmade.network/p/534/pangui/)). Its design is exactly what we'd want for both layers,
but it can't be planned around. If the engine ends up in C# or C++, re-evaluate.

### Clay, Taffy (building blocks)

[Clay](https://github.com/nicbarker/clay) is a roughly 4–5k-line C header: an immediate-mode flex-like layout with
a newer transition API, active in mid-2026. Its Rust binding [`clay-layout`](https://lib.rs/crates/clay-layout) is
behind (0.2, text in progress). [Taffy](https://docs.rs/crate/taffy/0.10.1) 0.10.1 (block, flex, grid) is the
shared layout core of bevy_ui, Blitz and Zed. These matter only if we write our own PanGui-like layer, which is
the plan C fallback.

### Godot Control nodes (Godot game-UI pick)

Godot 4.7 is current. It adds offset transforms on Controls (animate translate/rotate/scale without breaking layout),
and 4.6 decoupled mouse and keyboard focus ([4.7 summary](https://alternativeto.net/news/2026/6/godot-4-7-adds-arealight3d-asset-store-overhaul-gabe-support-and-hdr-output/)).
Fonts support MSDF, OpenType features and system fallback for CJK and emoji
([docs 4.7](https://docs.godotengine.org/en/stable/tutorials/ui/gui_using_fonts.html)). Juice comes from `Tween`,
`AnimationPlayer` and CanvasItem shaders. Building UI from code (no editor) works fine, and `.tscn`/`.tres` files
are text that agents can edit. For Rust on Godot, [`gdext-egui`](https://lib.rs/crates/gdext-egui) is stale (pinned
to 2024 gdext), so use imgui-godot or Controls for tools.

### NoesisGUI (fallback for the game layer)

XAML/MVVM with storyboards, vector rendering and Noesis Studio. All tiers are royalty-free and cover all platforms.
Indie is €195 per project (project budget under €250K, revenue under €100K)
([licensing](https://www.noesisengine.com/licensing.php)). Hytale is moving its UI to Noesis
([Q&A 2026-05](https://hytalemodding.dev/en/docs/qna/26-05-2026)). A community Rust wrapper,
[`noesis_runtime`](https://docs.rs/crate/noesis_runtime/latest), targets SDK 3.2.13. There's no Godot plugin, and
integrating with wgpu means implementing Noesis' RenderDevice **(effort unverified)**. It's closed source, which
clashes with "open-source foundations".

### Others, briefly

- **RmlUi**: C++ HTML/CSS-like UI with data bindings, transitions and animations. 6.1 is mature, but you write the
  render and input backend yourself. No Rust bindings worth trusting **(unverified)** ([repo](https://github.com/mikke89/RmlUi)).
- **Slint**: has an official `bevy-hosts-slint` example, but it uses the software renderer copied into a texture
  ([README](https://cdn.jsdelivr.net/gh/slint-ui/slint@1.16.0/examples/bevy/bevy-hosts-slint/README.md)). The licence
  is GPLv3 or royalty-free ([FAQ](https://github.com/ferrous-systems/slint/blob/master/FAQ.md)). Built for app UI.
- **gpui**: Zed doesn't publish it standalone. Forks (`gpui-pre-wgpu`, `open-gpui-wgpu`, Apache-2.0, pre-1.0) split
  off a wgpu renderer ([open-gpui-wgpu](https://docs.rs/crate/open-gpui-wgpu/0.1.0)). Embedding it in a game frame
  isn't a supported path.
- **Iced** 0.14 added time-travel debugging, hot reload and an animation API ([release](https://github.com/iced-rs/iced/releases/tag/0.14.0)).
  It's interesting as prior art for our scrub tooling, but it wants to own the app loop.
- **Xilem/Masonry/Vello**: Linebender's reactive stack. Still alpha **(unverified 2026 status)**.
- **Makepad**: 1.0 in 2025, with a live DSL reloaded without recompiling. App-focused, with CJK gaps at 1.0.
- **Ultralight** (WebKit on GPU): free under $100K revenue, but distribution terms are murky and the repo has been
  quiet since 2024 ([repo](https://github.com/ultralight-ux/Ultralight)). **Coherent Gameface**: the AAA HTML
  option, quote-only pricing, with Unity, Unreal and custom-engine integrations ([FAQ](https://coherent-labs.com/frequently-asked-questions)).
- **Rive**: excellent for animated widgets (an emote-wheel burst, goal-card flourishes), with an official
  [rive-bevy](https://github.com/rive-app/rive-bevy) on Vello. But authoring happens in Rive's GUI editor, which goes
  against code-first. Optional and later.

### s&box Razor: what to copy

`.razor` files compile to C# panel classes. Markup is a convenience; there's no web renderer. Capitalised tags are
panel types and `@` embeds C# ([razor panels](https://sbox.game/dev/doc/ui/razor-panels/),
[wiki](https://wiki.facepunch.com/sbox/UI/GettingStarted)). Panels rebuild only when `BuildHash()` changes, or on
`StateHasChanged()`. Styling is an SCSS subset on flexbox (Yoga docs referenced) with CSS transitions, plus
`:intro`/`:outro` pseudo-classes that animate creation and deletion. Razor edits need a game recompile, so
external stylesheets are recommended for fast hot reload ([wiki](https://wiki.facepunch.com/sbox/ui-razor)).
**Lessons:** (1) logic in compiled code, looks in a hot-reloaded sheet: the same split as bevy_ui + flair. (2) An
explicit rebuild hash is a cheap, debuggable form of reactivity. (3) `:intro`/`:outro` is the single most useful
juice primitive; copy it.

### Unity UI Toolkit (reference)

UXML/USS on flexbox (Yoga), live USS reload, SDF TextCore. 6.2 added world-space UI and 6.3 added UI Shader Graph (URP
only) ([status
post](https://discussions.unity.com/t/ui-toolkit-development-status-and-next-milestones-november-2025/1698009),
[docs](https://docs.unity3d.com/Manual/ui-systems/introduction-to-ui-shader-graph.html)). The current game's UI
interaction table maps directly onto USS transitions. That's the parity bar: bevy_ui + flair is the closest structural
match.

## Risks and unknowns

1. **Bevy churn.** BSN syntax changed in 0.20, `.bsn` files aren't shipped, and Feathers APIs were deprecated in
   0.19. Agents trained on older Bevy will write stale code, so pin the version and keep a local API cheat sheet.
2. **Single-maintainer crates** (`bevy_flair`, `bevy-inspector-egui`, `haalka`) lag Bevy releases. Mitigation:
   vendor them, or keep our juice kit small enough to own.
3. **Text quality under animation** in bevy_ui and egui: no MSDF found. Scale pops and big title text are the test.
4. **Localization:** Parley covers shaping and BiDi on bevy_ui. egui doesn't, but that only matters for tools.
5. **Subsecond hot-patching** is still "intermediate" (third-party, `dx` CLI). Its Bevy 0.20 compatibility is
   **unverified**.
6. **PanGui and Blitz timelines** are unknown. Don't block on either.
7. **Host undecided.** This whole recommendation flips to Control nodes if Godot wins.
8. **Noesis integration cost** (custom wgpu RenderDevice, community Rust wrapper) is unknown. Only spend on it if
   the spike fails.

## Spike proposal (3–5 days, on the chosen host; Bevy 0.20 assumed)

**Build:**
- **Dev tools (egui):** an entity picker and inspector over 1000 entities (a virtualized list), a timeline scrub
  slider over the snapshot ring, a net sim panel (latency, jitter and loss sliders, plus an RTT/rollback graph), a
  perf overlay, and one tuning slider that writes back to a text config.
- **Game UI (bevy_ui + BSN + flair):** a game HUD (goal card with check pop and slide-up, reticle, aim prompt
  with a "denied" wiggle, a counter that ticks up), the emote wheel (radial, stick or mouse select),
  a pause menu and the end card.
- **Timeboxed variant:** the emote wheel and pause menu in Blitz via `bevy_dioxus_render`, one day only, to price
  the HTML/CSS route.

**Pass/fail criteria:**
1. **Feel:** the FEEL.md §8 table can be reproduced in style files. Hover 80–120 ms with a 1.04–1.06 lift, press to
   0.95–0.97, release with ease-out-back, panel in 200–300 ms and out faster, toast queue. The developer judges it
   "moves like a toy" next to the Unity build.
2. **Gamepad:** the pause menu and end card are navigable with D-pad and stick using auto navigation, with at most
   2 manual edges per screen. The emote wheel selects by stick angle. Focus looks the same as hover.
3. **Text:** crisp at 1080p, 1440p and the Steam Deck's 800p, including during a 1.15× pop. A Japanese line and an
   emoji render with a fallback font. Strings come from a localization table.
4. **Hot reload:** a style edit is visible in under 1 s without a restart. A Rust edit to an egui panel is visible
   in under 5 s via subsecond, with sim state kept.
5. **Performance** (release build, M-series Mac and Steam Deck): HUD UI under 0.5 ms CPU per frame, and the
   inspector open with 1000 entities under 2 ms.
6. **Architecture:** the HUD only reads sim state (predicted for motion, verified for scores) and sends player
   input. Dev-tool edits go through the agent-API command path and survive replay.
7. **Agent test:** a fresh agent with only the repo docs adds a new widget (toast plus sound hook) and a new
   inspector field from a one-paragraph description, compiling first time or with one fix. Its screenshot via the
   agent API matches the description.

**Decision rule:** if 1–3 pass, adopt bevy_ui for the game UI. If feel or text fails, spike Noesis (2 days) before
considering plan C. egui for tools is adopted unless criterion 4 or 5 fails badly.
